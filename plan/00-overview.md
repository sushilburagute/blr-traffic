# Bengaluru ORR Traffic Simulator — Master Plan

## Context

Implementation contract additions and deviations are recorded in [implementation-notes.md](implementation-notes.md).
The implemented types preserve the required fields below and add replay events, snapshot identity/lane
arrays, bypass provenance, and an optional early-run endpoint in the worker protocol.

Build a browser-based, ₹0-to-run traffic simulator for the Outer Ring Road corridor
**Central Silk Board → Agara → Iblur → Bellandur → Kadubeesanahalli → Marathahalli** (~11 km, both directions).
The user picks how they'd commute (vehicle type × driving behaviour), configures a scenario (preset or expert
mode), watches the simulation on a real map, and gets an end-of-run report comparing their cohort's outcome
(travel time, speed, stops…) against the alternatives — e.g. *2W lane-cutter vs car lane-follower*.

Decisions already made with the user:

### Core modelling approach (agents in chunks 03–05 must follow this)
- **1-D longitudinal + discrete lanes.** Each vehicle has `(segmentId, lane, s, v)`. Geometry is only for
  rendering: `network.project(segmentId, lane, s) → [lon, lat, heading]` using the segment polyline and a
  per-lane lateral offset.
- **Car-following: IDM** (Intelligent Driver Model), params per vehicle type.
- **Lane change: MOBIL** (politeness `p`, safe-decel `bSafe`, threshold `aThr`), params per behaviour profile.
- **Lane discipline vs cutting** = behaviour profile changing MOBIL params + lane-change cooldown + gap acceptance.
- **3→4 lane squeeze**: a segment has physical width `W`. In *disciplined* mode usable lanes = `floor(W/3.5)`.
  In *squeeze* mode, when density on the segment > threshold and squeeze share > 0, a virtual extra lane
  appears (lane width 2.6 m) with a speed cap and a side-friction penalty applied to all lanes. Buses/trucks
  never use the virtual lane.
- **2W filtering**: a 2W whose leader is queued (v < 2 m/s) may enter a *filter lane* (between lanes) with
  speed cap ~15 km/h and reinsert at the queue head or at the stop line. Probability & cap from config.
- **Signals**: fixed-time phases per junction; amber running / red-light compliance probability per profile.
- **Obstacles**: point features `(segmentId, lanes[], s, type, speedCap)` — pothole (one lane, 5 km/h, prompts
  lane change), speed breaker (all lanes, 10 km/h). Randomly placed from seed unless expert-pinned.
- **Rain**: global multipliers (speed ×0.75, headway T ×1.3, accel ×0.8, obstacle speedCap ×0.6) + optional
  waterlogging spots (lane reductions). Toggleable live mid-run.
- **Determinism**: fixed `dt = 0.1 s`, seeded RNG, no `Math.random`, no wall-clock in `src/sim`. Same config +
  seed ⇒ identical result. Required for A/B comparisons.
- **Data layout**: vehicles in Structure-of-Arrays typed arrays (`Float32Array` for s, v, a; `Int16Array` for
  lane, segment; `Uint8Array` for type/profile/flags). Per-lane sorted index rebuilt each step (insertion sort —
  order barely changes). Target: 10k vehicles × 10 steps/s × 32× in a worker.

### Shared types (`src/sim/types.ts`) — authoritative shapes
```ts
export type VehicleType = 'twoWheeler' | 'auto' | 'car' | 'cab' | 'bus' | 'truck';
export type BehaviourProfile = 'disciplined' | 'opportunist' | 'aggressive';   // lane-follow → cut everything
export type Cohort = `${VehicleType}:${BehaviourProfile}`;
export type Direction = 'toMarathahalli' | 'toSilkBoard';

export interface VehicleTypeParams { length: number; width: number; vMax: number; a: number; b: number;
  T: number; s0: number; canFilter: boolean; canUseVirtualLane: boolean; }
export interface BehaviourParams { politeness: number; bSafe: number; aThr: number; lcCooldown: number;
  gapFactor: number; filterProb: number; amberRunProb: number; redRunProb: number; reactionTime: number;
  routeChangeProb: number; busLaneViolationProb: number; }

export interface ScenarioConfig {
  version: 1; seed: number; durationMin: number; startClock: string;      // "08:30"
  demand: { vehPerHour: number; profile: 'morning'|'evening'|'flat'|'custom'; customCurve?: number[];
    mix: Record<VehicleType, number>; behaviourMix: Record<BehaviourProfile, number>;
    throughShare: number; od?: number[][]; pulses: DemandPulse[]; };
  infra: { lanesOverride?: Record<string, number>; speedLimitKmh: number; busLane: boolean;
    flyovers: Record<JunctionId, boolean>; uTurns: Record<JunctionId, boolean>;
    encroachment: EncroachmentSpec[]; busStops: BusStopSpec[]; signals: Record<JunctionId, SignalPlan>; };
  disruptions: Disruption[];          // accident|breakdown|construction|waterlogging|illegalParking|brokenSignal|event|closure
  environment: { rain: boolean; rainIntensity: 0|1|2; potholes: number; speedBreakers: number;
    pinnedObstacles?: ObstacleSpec[] };
  behaviour: Record<BehaviourProfile, Partial<BehaviourParams>>;   // expert overrides
  squeeze: { enabled: boolean; densityThreshold: number; virtualLaneSpeedCapKmh: number };
  userCohort: Cohort;
}

export interface NetworkData {   // from data/corridor/network.json
  junctions: Junction[];         // id, name, lonlat, sOnCorridor, hasFlyover, signalDefault, crossRoadNames
  segments: Segment[];           // id, direction, fromJunction, toJunction, lanes, widthM, lengthM,
                                 // speedLimitKmh, polyline: [lon,lat][], cumulativeS: number[], kind: 'main'|'flyover'|'ramp'
  sources: Source[]; sinks: Sink[];
}

export interface Snapshot {      // worker → UI, transferable
  simTime: number; clock: string; count: number;
  pos: Float32Array;             // [lon, lat] × count
  heading: Float32Array; speed: Float32Array;
  type: Uint8Array; profile: Uint8Array; flags: Uint8Array;   // bit0 braking, bit1 filtering, bit2 virtualLane, bit3 userCohort
  signals: Uint8Array;           // per junction approach: 0 red 1 amber 2 green
  queues: Float32Array;          // per junction approach queue length (m)
  segmentSpeed: Float32Array;    // mean speed per segment (for heatmap)
}

export interface SimStats { /* see chunk 05 */ }
```

### Conventions
- `yarn` only. Scripts: `dev`, `build`, `lint`, `typecheck`, `test`, `test:e2e`, `data:fetch`, `data:build`.
- No `any`. ESLint + Prettier defaults from scaffold. Path alias `@/` → `src/`.
- `src/sim/**` must import nothing from React/DOM/Next. Enforced via an ESLint `no-restricted-imports` rule.
- Units: metres, seconds, m/s internally. Convert at the UI edge (`lib/units.ts`).
- Colours by vehicle type + behaviour are in `lib/colors.ts` and shared by map legend and charts.
