# Chunk 02 — Corridor data pipeline

**Goal:** Committed, curated `data/corridor/corridor.geojson` + `network.json` describing the ORR corridor
as a lane-graph the sim can run on and the map can draw.

Steps:
1. `scripts/fetch-corridor.ts` (run with `tsx`): Overpass QL query for OSM ways tagged
   `highway=trunk|primary|trunk_link|primary_link` with `name~"Outer Ring Road|ORR"` inside bbox
   `[12.905, 77.615, 12.965, 77.710]`, plus nodes tagged `highway=traffic_signals`, and ways with
   `bridge=yes` (flyovers) / `tunnel=yes` (underpasses). Save raw to `data/corridor/raw-overpass.json`
   (commit it — Overpass is rate-limited and we never want to depend on it at runtime).
   Retry with a 2nd Overpass mirror if the first fails.
2. `scripts/build-network.ts`: stitch ways into **one polyline per direction** between the six junctions,
   ordered by distance along the corridor. Emit `network.json` matching `NetworkData` with:
   - `junctions`: the 6 named junctions with lon/lat snapped to the polyline, `sOnCorridor`, cross-road names.
     Approx anchors to snap to (verify against OSM): Silk Board 12.9176,77.6227 · Agara 12.9230,77.6400 ·
     Iblur 12.9252,77.6610 · Bellandur 12.9295,77.6780 · Kadubeesanahalli 12.9390,77.6960 ·
     Marathahalli 12.9565,77.7010.
   - `segments`: main carriageway per direction between consecutive junctions (`lanes: 3`, `widthM: 10.5`,
     `speedLimitKmh: 60` defaults), flyover bypass segments where OSM shows `bridge=yes` at a junction
     (`kind: 'flyover'`, `lanes: 2`), and short ramp segments at each junction (`kind: 'ramp'`) for cross-road
     inflow/outflow.
   - `cumulativeS` per polyline vertex for O(log n) projection.
   - `sources`/`sinks`: both corridor ends + each junction's cross road (both directions).
   - `signalDefault` per junction: 4-phase, 120 s cycle, 45 % green to ORR through-movement.
3. `src/sim/network/index.ts`: `loadNetwork(json)`, `project(segmentId, lane, s)`, `laneOffset(segment, lane)`
   (right-hand-drive: lane 0 = rightmost/fast lane, lanes increase to the left/kerb), `nextSegments(segmentId)`,
   `approachOf(segmentId)` → junction approach index. Unit tests: projection monotonic, lengths match.
4. `data/corridor/corridor.geojson`: FeatureCollection for rendering — segment LineStrings (with `lanes`,
   `kind`), junction Points, source/sink Points. Generated by the same script.
5. Sanity script output: total length per direction (expect ~10.5–11.5 km), segment count, flyover list.
   Record actual numbers in `data/corridor/README.md`.

**Done when:** `yarn data:build` regenerates identical output from the committed raw file; tests pass;
a quick MapLibre check (chunk 07 will do it) shows the polylines on the real road.

**Fallback if Overpass is unavailable:** hand-trace the polylines from the anchor coords with ~20 vertices per
segment, flag `network.json.meta.source = 'hand-traced'`, and leave the fetch script in place.
