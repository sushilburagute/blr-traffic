# Implementation notes

The application runs entirely in a browser worker and has landing, simulation, report, guide, and compressed
share routes. Real OSM carriageways and their raw extract are stored in `src/data/corridor`; public copies
are generated by the same deterministic data builder. Flyover/underpass deck geometry is an assumed final
700 m of its associated main segment, with a safe merge at the split point.

## Contract extensions

`src/sim/types.ts` is the implemented contract. Original required fields are preserved. Added fields:

- `ScenarioConfig.liveEvents?`: fixed-tick rain changes and incident additions, so live edits replay exactly.
- `Snapshot.ids`, `segment`, `lane`, `effectiveLanes`: stable vehicle identities, accurate tooltips and exact
  virtual-lane rendering. These typed arrays participate in the same buffer recycling protocol.
- `Segment.bypassFor?` and `osmWayIds?`: main/bypass association and geometry provenance.
- `ToWorker.skipToEnd.untilS?`: report an early endpoint without changing the original demand curve.
- `SimStats.config` and `finished`: report provenance and distinction between completed and early runs.

## Implementation choices and limits

- Node 22 is pinned rather than the plan's Node 20. Yarn Classic is used, with a committed lockfile.
- The default demand now uses 12,000 veh/h and terminal signal cycles of 180/150 s. They are modelling
  assumptions; the scenario is not calibrated against measured traffic.
- A named U-turn adds merge friction and a sink/source return trip for an assumed 5% of eligible exits.
  A vehicle can make at most one such return trip; turning arcs are not rendered separately.
- Rain affects speed, headway, acceleration, demand mix and waterlogging. Potholes use reduced wet speed
  caps and a seeded 50% per-encounter late-visibility probability.
- Encroachment and closures reduce accessible lanes; vehicles heading toward a closed next segment exit at
  the previous junction. Fine-grained service-road route choice is simplified.
- Expert sliders cover core settings. Less common arrays and matrices use validated JSON editors.
- UI controls use small Radix/shadcn-style primitives and semantic native controls rather than generating
  unused copies of the full shadcn component catalogue.
- MapLibre/deck.gl use a non-interleaved overlay. Vehicle positions are extrapolated for at most 50 ms
  between snapshots using reusable buffers. Overview is top-down and rotates the corridor horizontally.
- The loading screen tracks network, style, atlas, worker warm-up, renderer import, and junction tile
  prefetch at zooms 13–15. Missing basemap tiles fall back gracefully and can load on demand.
- Non-hashed data URLs use bounded cache lifetimes instead of year-long immutable caching.
- Queue thresholds are labelled model categories because an authoritative BTP citation was not verified.
- Annual delay and congestion use completed end-to-end trips; reports explain completion bias and missing
  samples. TomTom is contextual citywide data, not a calibration target.
- Vercel deployment, custom-domain DNS, GA DebugView, and external social-card validation need account
  access and have not been verified in this implementation session.

Performance results and outstanding performance targets are recorded in `notes-perf.md`.
